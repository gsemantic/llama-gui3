# Контракт: архив сессий (RAG-сжатие)

> **Статус:** согласовано (2026-11-25).
> **Область:** плагин `wp_coder` (инструменты `archive_*`), хост
> `llama-gui` (RAG v2, скоуп `plugin:wp_coder:archive`).
> **План:** `docs/RAG_SESSION_ARCHIVE_PLAN.md`. **Фундамент:** RAG v2
> (`docs/RAG_PLUGIN_SERVICE_PLAN.md`, M1–M5 закрыты).

## 1. Зачем

Компакшн обрезает длинный вывод инструмента в сводке (порог
`limits::kSummaryToolOutputChars` = 2000 символов), и оригинал терялся.
Архив заменяет «обрезано» на «можно найти»: полный вывод пишется в
изолированный RAG-скоуп с точным локатором, а в контекст уходит короткий
локатор.

## 2. Скоуп и изоляция

* Один скоуп на плагин: **`plugin:wp_coder:archive`**.
* Поиск в архиве не видит чужие скоупы (изоляция RAG v2, критерий 4).
* Очистка — по `session_id` внутри скоупа, а не скоупом целиком.

## 3. Локатор

Формат: **`session_id:call_id`** (+ `file:line` оригинала, если задан).

* Локатор кладётся в **РЕЗУЛЬТАТ** инструмента (и в заголовок документа
  архива), а не в сводку компакшна.
* По локатору агент достаёт оригинал инструментом `archive_search`.
* `file:line` в результате — из аргументов (исходный файл), а не из
  метаданных архивного чанка: `file_path` чанка указывает на сам файл
  архива.

## 4. Что архивируется

* Только выводы **выше порога** `limits::kSummaryToolOutputChars`
  (2000 символов) — то, что компакшн всё равно обрезал бы.
* Запись — на уровне инструментов (цикл агента после `ToolRunner::run`),
  **компакшн не трогается**: он видит уже короткий результат-локатор.

## 5. Инструменты

| Инструмент | Роль | Ключ/флаги |
|---|---|---|
| `archive_write` | записать полный текст с локаторами | `rag`, WRITES_FILES\|DESTRUCTIVE\|SLOW |
| `archive_search` | найти по содержимому/по `call_id`, вернуть локаторы + `file:line` | `read`, READ_ONLY |
| `archive_clear` | очистить архив по `session_id` | `rag`, WRITES_FILES\|DESTRUCTIVE\|SLOW |

## 6. Персистентность и квоты

* Архив переживает рестарт: документ — постоянный файл под
  `data_dir/wp_coder/archive/<session_id>/<call_id>.txt` (не временный),
  индекс — host R4.4 (`RagStore` на диске).
* Квоты/дедлайн — host R4.2; плагин передаёт пустой `opts` (значения по
  умолчанию скоупа).

## 7. Дедуп

Повторный вызов с тем же `call_id` не дублирует архив: путь документа
ключуется `call_id`, а хост не индексирует один путь дважды (R1.6,
`RagStore::index_document`).

## 8. Деградация (честная, не молчаливая)

| Ситуация | Поведение |
|---|---|
| Старый хост без RAG v2 | `archive_write`/`archive_search` — внятный отказ; автоматическая запись (A1.1) не срабатывает, результат инструмента не меняется |
| Нет `path_data_dir` | `archive_write` — отказ «архив некуда писать»; A1.1 молчит (старое поведение) |
| Пустой поиск | `archive_search` различает «выключено» (`code=disabled`) и «пусто» через `rag_scope_info` (R5.2) |
| `archive_clear` на старом хосте | файлы сессии удаляются, индекс — нет; в ответе честно «не удалось убрать из индекса: N» |
| Документ без заголовка архива | `archive_search` показывает `file_path:start_line`, локатор не выдумывает |

## 9. Что НЕ делаем

* Не меняем формулу/инварианты компакшна (`compaction.*`).
* Не меняем хостовый RAG-API (RAG v2 закрыт в M5).
* Не трогаем KV-cache префиксов и облачный RAG.
