# План: архив сессий на RAG (RAG-сжатие) — следующая тема

> **Статус:** проект, на согласование (2026-11-25).
> **Область:** плагин `wp_coder` (политика компакшна + архив), хост `llama-gui`
> (RAG-сервис, уже готов — `docs/RAG_PLUGIN_SERVICE_PLAN.md`).
> **Не область:** изменение хостового RAG-API (RAG v2 закрыт в M5); KV-cache
> префиксов; новая модель эмбеддингов.
> **Как обновлять:** правила §10 (одна задача — один коммит; чекбокс §4 +
> строка §5 + запись §7 в том же коммите).
> **Связь:** §11 `RAG_PLUGIN_SERVICE_PLAN.md` — форвард-ссылка, не план.

## 1. Цель и границы

### 1.1. Цель

Заменить «обрезано в 2000 символов» на «можно найти»: полный вывод
инструмента/свёрнутый ход пишется в изолированный архив-скоуп
`plugin:wp_coder:archive` с точными локаторами (`session_id`, `call_id`,
`file:line`), а в сводку/контекст попадает **локатор**, по которому агент
может достать оригинал через `rag_search_ex`.

### 1.2. Критерии успеха (проверяемые)

1. Вывод инструмента, обрезанный компакшном, полностью лежит в архиве и
   находится по `archive_search` по `call_id`.
2. Сводка содержит локатор (`session_id:call_id`), а не только «обрезано».
3. Архив переживает перезапуск приложения и выгрузку плагина.
4. Поиск в архиве не видит чужие скоупы (изоляция RAG v2).
5. Квоты/дедлайн: индексация архива прерывается по «стоп» и не растёт
   линейно по числу сессий.
6. Старое поведение (без архива) не ломается: компакшн остаётся
   самодостаточным.

### 1.3. Границы (что НЕ делаем)

| Не делаем | Почему | Где |
|---|---|---|
| Меняем формулу компакшна | `compaction.*` самодостаточен, ломать инварианты нельзя | отдельная тема |
| Меняем хостовый RAG-API | RAG v2 закрыт (M5); `plugin:wp_coder:archive` уже выразим | — |
| KV-cache префиксов | требует поддержки слотов в хосте | отдельно |
| Облачный RAG | локальный сервер уже есть | вне рамки |

## 2. Термины

| Термин | Значение |
|---|---|
| **Архив** | Скоуп `plugin:wp_coder:archive`: полные выводы/свёрнутые головы с локаторами |
| **Локатор** | Строка `session_id:call_id` (+ `file:line`), по которой достаётся оригинал |
| **Свёрнутый ход** | Ход, попавший под компакшн (выброшен/обрезан из контекста) |
| **Компакшн** | Существующая политика `compaction.{h,cpp}`: что и как сжимать |

---

## 3. Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│ wp_coder: compaction (политика) + archive (хранилище)        │
│   select_to_compact() → свернуть → ЛОКАТОР в <prior-summary> │
└───────────────┬─────────────────────────────────────────────┘
                │ rag_index_document_ex / rag_search_ex (RAG v2)
                ▼
┌─────────────────────────────────────────────────────────────┐
│ Хост: RagRegistry → RagStore «plugin:wp_coder:archive»       │
│   (уже есть: скоупы, квоты, async, персистентность)          │
└─────────────────────────────────────────────────────────────┘
```

* Архив — **ещё один скоуп**, не новый механизм: плагин пишет через
  `rag_index_document_ex("plugin:wp_coder:archive", …)`, ищет через
  `rag_search_ex`. Хост не меняется.
* Компакшн остаётся **политикой плагина**: хост даёт хранилище и поиск, но
  не решает, что выбрасывать.
* Локатор — единственный мост между сводкой и архивом: сводка не тащит
  полный текст, но ссылается на него.

## 4. Задачи

Формат: `[ ]` не начато, `[~]` в работе, `[x]` закрыто, `[!]` заблокировано.
У каждой — «Готово, когда» и тест.

### A0 — «не врать и не терять» (без изменений компакшна)

- [ ] **A0.1** Инструмент `archive_write` (или `session_archive`): пишет
      полный текст с локаторами в скоуп `plugin:wp_coder:archive`.
      *Готово, когда:* тест пишет и находит по `call_id`.
- [ ] **A0.2** `archive_search` (или `rag_query` с суффиксом `archive`):
      возвращает локаторы + `file:line`.
      *Готово, когда:* тест находит по содержимому и по `call_id`.

### A1 — подключить архив к компакшну

- [ ] **A1.1** При обрезании вывода компакшн пишет полный текст в архив и
      кладёт **локатор** в `<prior-summary>` (а не «обрезано»).
      *Готово, когда:* тест: сводка содержит `session_id:call_id`, архив
      содержит оригинал.
- [ ] **A1.2** Повторное сжатие не дублирует архив (дедуп по `call_id`).
      *Готово, когда:* тест: два сжатия → один чанк в архиве.

### A2 — «можно найти» вместо «обрезано»

- [ ] **A2.1** `rag_query`/`archive_search` по архиву; при пустом результате
      — честная причина (`disabled`/`empty`), как в R5.2.
      *Готово, когда:* тест различает «выключено»/«пусто».
- [ ] **A2.2** Убрать из текста «обрезано в 2000» подсказку «ищи в архиве».
      *Готово, когда:* тест на текст ответа.

### A3 — персистентность, квоты, очистка

- [ ] **A3.1** Архив переживает рестарт (R4.4) и ограничен квотами (R4.2).
      *Готово, когда:* тест «создали → записали → рестарт → нашли».
- [ ] **A3.2** Политика очистки: `archive_clear`/по `session_id`; не трогает
      чужие скоупы.
      *Готово, когда:* тест: очистка A не трогает B.

### A4 — принятие

- [ ] **A4.1** Документ `docs/SESSION_ARCHIVE_CONTRACT.md` (локаторы,
      квоты, деградация).
- [ ] **A4.2** `wp_coder/CHANGELOG.md` + версия.

*Готово, когда:* агент находит полный вывод по локатору из сводки; архив
переживает рестарт; компакшн не сломан.

## 8. Риски и митигации

| Риск | Вероятность | Последствие | Митигация |
|---|---|---|---|
| Архив растёт на диске | средняя | заполнение | квоты R4.2 + `archive_clear` по `session_id` |
| Локатор «протух» (файл удалён) | средняя | поиск не находит | `rag_scope_remove_document` при удалении; честный `empty` |
| Дубли при повторном сжатии | высокая | раздувание | дедуп по `call_id` (A1.2) |
| Сводка тащит полный текст | средняя | переполнение | в сводку — только локатор, не текст |
| Смена поведения компакшна | средняя | жалобы | A0/A1 аддитивны; старое поведение не ломается |

## 10. Правила обновления плана

1. Одна задача — один коммит; вместе с кодом меняются §4, §5, §7.
2. Не перенумеровывать закрытое; новая итерация — `A5`.
3. Статусы: `[ ]`/`[~]`/`[x]`/`[!]`.
4. Критерий приёмки обязателен.
5. Тест — часть задачи, обязан падать на мутации.
6. Отклонение — в §7 с причиной.
7. Перед следующей сессией читать §4: первая `[ ]` — текущая.
