# Контракт парсера сайтов для RAG-сервиса хоста (RAG v2)

> **Статус:** контракт для плагина-парсера сайтов (второй потребитель RAG v2
> после `wp_coder`). Соответствует ABI `LlamaHostApi` RAG v2 и плану
> `docs/RAG_PLUGIN_SERVICE_PLAN.md` (R5.3).
> **Аудитория:** разработчик плагина, который индексирует веб-страницы в
> собственный изолированный индекс и хочет искать по ним.

## 1. Модель скоупа

Один домен — один скоуп. Имя скоупа строит **хост** из идентичности плагина;
плагин передаёт только суффикс (домен):

```
plugin:siteparser:example.com
```

* Суффикс — домен без схемы и порта (`example.com`, `docs.example.com`).
  Двоеточие в суффиксе запрещено (это разделитель скоупа); точка и дефис
  разрешены.
* Плагин НЕ передаёт путь и НЕ выбирает каталог: хост выводит
  `<data_dir>/rag_scopes/plugin_siteparser_example_com/` и проверяет, что
  результат внутри `rag_scopes/`.
* Скоупы изолированы: `search` в `example.com` не возвращает документы
  `other.com`.

## 2. Корни и белый список

Корни (`roots`) — host-owned настройка `plugin.<name>.rag.roots` (массив
путей). Плагин индексирует только то, что скачал сам, но хост может
фильтровать выдачу по `path_filter`. Не индексируйте секреты (`*.env`,
`*.key`, `_secrets`) — это ответственность плагина и `roots`.

## 3. Квоты

На каждый вызов `rag_index_document_ex` (или `rag_index_start`) передаётся
`opts_json`:

```json
{"max_bytes": 524288, "max_chunks": 200, "deadline_ms": 5000, "reindex": false}
```

| Поле | Смысл | Кламп |
|------|-------|-------|
| `max_bytes` | предел байт одной страницы | 1 ГиБ |
| `max_chunks` | предел чанков страницы | 100000 |
| `deadline_ms` | дедлайн индексации страницы | 24 ч |
| `reindex` | переиндексировать изменённую страницу | — |

Превышение → `truncated=true` + `reason`; отмена/дедлайн → частичный
результат. `0` = «как в настройках скоупа».

## 4. HTML/CSS через AST

`.html`/`.htm` индексируются как **текст** (документация), а `.css` — как
**код** (tree-sitter AST-чанкинг с `symbol_name`/`start_line`/`end_line`).
Если нужно индексировать HTML как код (секции/теги) — используйте явный
`parse_code()` на стороне хоста; тип `detect_content_type` при этом остаётся
Text («чем читать» и «что за язык» — разные вопросы).

## 5. Инкрементальная индексация

* Повторная индексация того же `path` без `reindex` — no-op (дедупликация
  по профилю стора).
* Изменившуюся страницу индексируйте с `"reindex": true` — старые чанки
  убираются, добавляются новые.
* Удаление страницы: `rag_scope_remove_document(scope, path)` (идемпотентно).

## 6. Отмена (тысячи страниц)

Для тысяч страниц используйте асинхронную пару, а не синхронный
`rag_index_document_ex`:

```
handle = rag_index_start(host, scope, path, opts_json);
loop:
    r = rag_index_wait(host, handle, /*timeout_ms=*/200);
    if r.code == "timeout":  // ещё индексируется
        if user_pressed_stop: rag_index_cancel(host, handle);
        continue;
    break;                    // r.ok == true, handle освобождён
```

`rag_index_cancel` ставит атомарный флаг, проверяемый в цикле чанков; отмена
не откатывает уже добавленные чанки (частичный результат). `wait` освобождает
handle только по завершении — `cancel` зовите, пока handle жив.

## 7. Коды ответов

| Код | Значение | Действие парсера |
|-----|----------|------------------|
| `disabled` | RAG выключен (глобально или плагину) | сообщить пользователю, не ретраить |
| `unavailable` | реестр не настроен | проверить хост |
| `denied` | нет права `rag_write`/`rag_access` | добавить право в манифест |
| `bad_scope` | скоуп не принадлежит плагину | исправить суффикс (домен) |
| `bad_request` | пустой путь/запрос, битый `opts_json` | исправить аргументы |
| `quota` | квота исчерпана (`truncated=true`) | увеличить квоту или пропустить |
| `bad_index` | индекс повреждён/несовместим | переиндексировать (`reindex`) |

## 8. Права

Манифест плагина должен объявлять `rag_access` (чтение) и `rag_write`
(индексация/удаление/очистка). Без них `_ex`-функции отвечают `denied`.
Запись `plugin.<self>.rag.*` запрещена namespace-гардом — настройки RAG
host-owned.
