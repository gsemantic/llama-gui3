## 1. Архитектура и субагенты
Создать композитный `wp_coder_orchestrator`, который делегирует задачи:
- **wp_theme_agent** — генерация тем (style.css, functions.php, index.php), хуки, локализация.
- **wp_plugin_agent** — генерация плагинов (заголовок, активация/деактивация, шорткоды, REST, Gutenberg-блоки).
- **wp_hook_agent** — поиск/генерация фильтров и экшенов, карта хуков.
- **wp_deploy_agent** — деплой (rsync, WP-CLI), миграции БД, откаты.
- **wp_rag_agent** — RAG по кодовой базе WP (ядро, темы, плагины).
- **wp_terminal_agent** — выполнение WP-CLI и безопасных shell-команд.
- **wp_file_agent** — операции с файлами с политиками для wp-content.

## 2. Harness-профили для моделей
Профили в `profiles/wp_coder/`:
- **fast_local.json** — локальная модель, короткие промпты, без RAG.
- **accurate_cloud.json** — облачная модель, длинные промпты, с RAG.
- **secure_audit.json** — строгая валидация, запрет опасных команд, только белый список.
- **debug_verbose.json** — максимальная детализация логов.

Каждый профиль: `model`, `temperature`, `max_tokens`, `tools_policy`, `timeout_ms`, `allowed_commands`, `allowed_extensions`, `rag_enabled`.

## 3. Замена заглушек на реальные инструменты
- **code_agent**: подключить реальные LLM-вызовы, форматтеры (clang-format/black), линтеры.
- **rag_agent**: подключить к существующему `core::RagManager`.
- **terminal_agent**: использовать существующий `TerminalAgent` с белым списком.
- **file_agent**: использовать существующий `FileAgent` с политиками для wp-content.

## 4. Middleware и политики
- **Guardrails**: запрет опасных команд, проверка путей (только wp-content), лимиты на размер файлов.
- **Telemetry**: логирование действий, метрики, привязка к thread_id.
- **Budget**: лимиты на токены/время, квоты.

## 5. Интеграция с WordPress
- **WP-CLI**: обёртка через `wp_terminal_agent`.
- **RAG-корпус**: ядро WP, документация, популярные темы/плагины.
- **Валидация**: проверка PHP через `php -l`, JSON схем, WPCS.
